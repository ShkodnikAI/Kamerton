# self-host/miniapp — Mini App (страница практик)

Страница практик фазы M2 (концепция: `docs/concept-v2.md`): пейсер дыхания
и PPG через камеру — HTML/JS в браузере телефона, единственное разрешённое
исключение из §1 AGENTS.md. Вычисления исполняются на устройстве владельца;
RR-ряд наружу не уходит (инвариант 7).

## Канал доставки

ADR-0002, вариант (а) «приватный туннель»: телефон входит в приватную сеть
владельца (WireGuard/Tailscale), страницу отдаёт `mlog serve` Камертона
маршрутом `GET /miniapp`. Порты наружу остаются ноль; https внутри tailnet
делает возможной кнопку Mini App позже.

## Авторизация

Токен владельца: переменная `KAMERTON_MINIAPP_TOKEN` (deploy/env.allowlist —
SSOT; при деплое добавить строку в `/data/kamerton/env` И дополнить значение
`METALOGOS_ENV_ALLOWLIST` — установленный env-файл install.sh не
перегенерирует). Токен передаётся параметром `t` в адресе страницы:

```
https://<tailnet-адрес>:8461/miniapp?t=<KAMERTON_MINIAPP_TOKEN>
```

Каждый запрос к сессионному API несёт тот же параметр. Дополнительно
маршруты закрыты csrf-мидлварью (double-submit №262): GET страницы выдаёт
куку `_mlog_csrf`, каждый POST обязан нести её значение в `X-CSRF-Token`
(страница делает это сама; TTL 15 минут — при истечении страница
перезагружается). Мутации POST-маршрутов без куки/заголовка отвечают 403.

Токен — alphanumeric (мост `escape_html` над `query_param` точен для такого
алфавита); не используйте в нём `& < > " '`.

## Состояние на Н2-06 (пейсер + PPG + протокол перебора)

- `index.html` — канон страницы; отдаётся из ДОВЕРЕННОГО литерала в
  `src/miniapp/miniapp.mlog` (`miniapp_html()`), байт-равенство пиннуто
  тестом lockstep (read_file-результат не отвечает на запросы — граница
  утечки №391).
- **Пейсер (Н2-04)**: темп 4.5–7.0 вдох/мин с шагом 0.25 (клампы UI),
  плавная синусоидальная анимация вдох/выдох (равные половины, масштаб
  0.10–1.00, фаза от абсолютного времени — без накопления дрейфа),
  таймер две минуты на темп (протокол концепции, 11 шагов на полный
  перебор); отметка каждого завершённого шага — `{step, tempo_bpm}` —
  пишется в сессию инкрементально. Скрипт-проверка против эталонной
  раскадки на трёх контрольных темпах:
  `node self-host/miniapp/test/pacer-test.mjs`.
- **PPG (Н2-05)**: запись с камеры (getUserMedia, фронтальная; кадры
  умирают в canvas 8×8 — средний зелёный канал центральной области,
  сырые кадры нигде не хранятся и не передаются — инвариант 7);
  извлечение RR-ряда сердечного пульса на устройстве (скользящая база
  1.5 с → AC → эпохи 10 с → пики с рефрактером 300 мс → межпиковые
  интервалы, полоса 300–2000 мс = 30–200 уд/мин); контроль качества по
  эпохам (пики ≥ 5, RR в полосе, CV ≤ 0.25, амплитуда ≥ 6× шумовой
  пол) — брак ловится громко (эпох < 2, отбраковка > 50%, RR < 8 →
  отказ с причиной, сохранение не происходит); сохранение RR в сессию
  (`rr_json`, `rr_source='ppg'`) — только по явному действию владельца.
  Пик дыхания ~0.1 Гц появится в СПЕКТРЕ сердечного RR-ряда (Н2-06,
  RSA), а не в сырых интервалах. Скрипт-проверка (синус-мок 60 bpm →
  RR 1000±50 мс; 60/75/100 уд/мин; три случая громкого брака):
  `node self-host/miniapp/test/ppg-test.mjs`.
  Приёмка «эталонный пульсометр: расхождение среднего RR ≤ 5%» — шаг
  владельца на устройстве при деплое (заявлено в PR).
- **Протокол перебора (Н2-06)**: сессия `kind=sweep` — полный проход 11
  темпов по две минуты с записью пульса на каждом шаге (переключатель
  «писать пульс во время шагов»). Отметка шага несёт свой RR-сегмент:
  `{step, tempo_bpm, rr, rr_reason}` (поле `rr` присутствует всегда;
  брак QC едет громко в `rr_reason`, протокол продолжается). «Завершить»
  шлёт `final=1` — ТОЛЬКО финальное закрытие запускает серверный анализ:
  спектр каждого сегмента билтинами Ломба–Скаргла (№591:
  `lomb_scargle`/`spectral_peak`), резонанс = темп шага с максимальной
  долей мощности; принятая прогонка пишется в таблицу `sweep_result`
  (инвариант 6) и зеркалится в kv (`resonance_*`).
  **Предрегистрация допуска (зафиксирована в наряде до просмотра живых
  данных):** шаг годен, если его спектр не деградировал (пол языка —
  12 точек RR); протокол принимается при ≥ 6 годных шагах из 11;
  повторная прогонка воспроизводит резонанс при сдвиге ≤ 0.3 вдоха/мин
  и отношении доли мощности [0.5; 2.0] к предыдущей (вердикт
  `reproducible`/`divergent` в таблице и ответе). Приёмка «повторная
  прогонка на живых данных воспроизводится» — шаг владельца после
  деплоя (заявлено в PR). Скрипт-проверка сборщика сегментов:
  `node self-host/miniapp/test/sweep-test.mjs`.
- Журнал сессий работает целиком: `POST /miniapp/session` открывает строку
  в таблице `practice_session` (SQLite, инвариант 6), «Завершить» закрывает.
  Читается любым sqlite3 клиентом.
- Камера требует защищённый контекст (https) — канал ADR-0002 (а)
  (tailnet) его даёт; http-закладка вариант (б) камеру НЕ даст.

## Сессионное API (сводка)

| Маршрут | Параметры | Ответ |
|---|---|---|
| `GET /miniapp` | `t` | HTML-страница (или 403) |
| `POST /miniapp/session` | `t, kind=pacer\|ppg\|sweep, tempo_bpm, steps_total, arm_id?, trial_id?` | `{"id":N}`; 400 при мусоре |
| `POST /miniapp/session/close` | `t, id, steps_done, step_marks(JSON), rr_json(JSON), rr_source=ppg\|manual, final?` | `{"updated":1}`; для sweep+final=1 — `{"updated":1,"sweep":{ok,resonance_bpm,share,verdict,…}}`; 404 — неизвестный id |

Тела запросов не используются: на 0.30.0 парсеры тела
(`json_body`/`form_data`/`request_body`) возвращают пустую структуру
(заявлено громко в worklog наряда, задание агенту Metalogos-), поля идут
процент-декодированными query-параметрами.
