# ADR-0002 · Доставка Mini App до телефона

Дата: 2026-10-09
Статус: принят — вариант (а) приватный туннель (слово владельца в
чат-сессии 2026-10-09: «А»; совпадает с рекомендацией исполнителя)
Затрагивает: инвариант 7 (AGENTS.md §6), сетевую позу концепции (long polling,
ноль входящих портов), наряды Н2-03…Н2-07 (ссылка на этот ADR в Шаге 0)

## Контекст

Фаза M2 («Соматика») требует Mini App: пейсер дыхания и PPG через камеру —
HTML/JS в браузере телефона, единственное разрешённое исключение из §1
AGENTS.md. Вычисления исполняются на устройстве владельца: пейсер рисует ритм,
извлечение пульсового сигнала и RR-интервалов идёт в JS, сырые кадры никуда
не сохраняются. Наружу сигналы не уходят — но саму страницу ещё нужно
доставить до телефона, а публичного адреса у сервера нет и по концепции
не будет.

Сетевая поза (снята по Шагу 0 наряда Н2-02): связь с Telegram — long polling,
входящих портов ноль; сервис живёт в WSL2 на Windows 10; наружу — только
исходящие соединения. Концепция прямо требует отдельного ADR на туннель:
«переход на туннель потребует отдельного ADR». Инвариант 7: голос, отклики,
нота, пульс обрабатываются локально; наружу — только публичные запросы к
научным базам. Любой канал доставки обязан сохранить обе позы: ноль открытых
портов и данные в пределах машины владельца.

Ограничение, не зависящее от варианта: официальная кнопка Mini App в Telegram
открывает только https-адреса. Канал доставки без https означает, что страница
открывается мобильным браузером по закладке, кнопки в боте нет.

## Альтернативы

### (а) Приватный туннель — телефон в сети владельца

WireGuard-туннель (практически — Tailscale как управляемая обвязка): телефон
входит в приватную сеть владельца, `mlog serve` отдаёт страницу маршрутом.
Порты наружу по-прежнему ноль — туннель держит только исходящие соединения,
та же поза, что у long polling. `tailscale serve` выдаёт валидный https
внутри tailnet — кнопка в Telegram становится возможной, если владелец
захочет её позже.

- Инвариант 7: полезная нагрузка (RR-ряд, сводки сессий) идёт телефон →
  сервер внутри E2E-зашифрованного WireGuard-канала; ретранслятор DERP,
  если прямой путь не найден, передаёт шифротрафик и полезной нагрузки
  не видит. Строгое чтение («байт не покидает дом») не выполняется для
  координационных метаданных (ключи, адреса — координатору); полезная
  нагрузка не покидает контура устройств владельца.
- Поведение при ребуте: служба на Windows автостартует; проксирование в WSL2
  идёт по localhost и не зависит от смены внутреннего IP WSL — самый
  ребут-стойкий из трёх вариантов на этой ОС.
- Цена поддержки: клиенты на двух устройствах (Windows + телефон), аккаунт
  координатора, отзыв устройства при утере телефона. Наличие WireGuard/
  Tailscale на устройствах владельца из среды исполнителя не снимается —
  проверка при выборе (влияет только на объём разовой настройки).

### (б) LAN-only — практики только в домашней сети

Телефон в домашнем Wi-Fi открывает `http://<адрес-сервера>:8461/…` напрямую.
Ноль новых сущностей и ноль наружных зависимостей; строгое выполнение
инварианта 7 — байты данных не пересекают границу дома. Практики привязаны
к дому (утро и вечер), покрытие сессий полное; вне дома пейсер и PPG
недоступны. http без https — страница по закладке, без кнопки в боте.

- Инженерная цена на Windows 10 + WSL2: входящие из LAN пробрасываются
  `netsh portproxy` и правилом брандмауэра на Windows-хосте; внутренний IP
  WSL2 меняется при перезагрузке, portproxy ведёт на устаревший адрес —
  нужен хостовый скрипт обновления в автозагрузке (§1) и проверка
  доступности после каждого ребута. Отказ тихий: бот продолжает работать,
  а практики молча недоступны.
- Поведение при ребуте: до отработки скрипта обновления portproxy канал
  недоступен; дисциплина проверки после ребута ложится на владельца.

### (в) Статический файл — всё на устройстве

HTML/JS-файл доставляется на телефон один раз файлопередачей и открывается
локально; пейсер и PPG работают без всякой сети; сессии копятся на
устройстве, сводка переносится в SQLite руками.

- Инвариант 7 соблюдён буквально, цена поддержки нулевая.
- Однако сессии практик обязаны жить в SQLite (инвариант 6, Н2-03):
  ручной перенос делает запись сессии делом памяти владельца — трение
  порождает пропуски, ровно то, от чего проект уходит. Несовместим с Н2-03
  в текущей редакции («маршрут отдачи в serve-программе», «страница
  открывается по каналу ADR-0002»): выбор (в) требует переработки Н2-03
  отдельным нарядом.

## Рекомендация исполнителя

Вариант (а): на Windows 10 + WSL2 он единственный ребут-стойкий без ручной
дисциплины, даёт https и запас на кнопку Telegram, а полезная нагрузка
остаётся внутри E2E-туннеля между устройствами владельца. Вариант (б) —
выбор при строгом чтении инварианта 7 (ноль наружных сущностей) ценой
хрупкого portproxy и домашней географии практик. Вариант (в) отклоняется:
ломает автоматическую запись сессий в SQLite.

## Решение

Вариант (а) — приватный туннель (WireGuard, практически Tailscale):
телефон входит в приватную сеть владельца, `mlog serve` отдаёт страницу
маршрутом; порты наружу остаются ноль, https внутри tailnet делает
возможной кнопку Mini App позже. Слово владельца в чат-сессии
2026-10-09 — «А»; выбор совпадает с рекомендацией исполнителя.

Следствия: Н2-03 строит маршрут отдачи и авторизацию токеном владельца
по этому каналу; наличие WireGuard/Tailscale на устройствах владельца
проверяется при разовой настройке канала (не блокирует код); поведение
при ребуте — автостарт службы Windows + проксирование по localhost
(рёбут-стойкий вариант по разделу (а) выше).
