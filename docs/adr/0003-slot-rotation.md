# ADR-0003 — Слоты и ротация активного набора

Статус: **принят владельцем 2026-10-24** (чат, issue #75): режим — автоматическая
ротация; числа ниже (25 / 0,10 / 0,90 / 14 / 90) — «согласен». Правило зафиксировано
ДО данных и меняется только новым ADR. Код автоматической замены — отдельный наряд
(Н3-06); пока она не написана, активный набор меняется вручную через `activate_arm` /
`deactivate_arm` (выбор практик владельцем — Н3-05).

## Контекст

Практики идут параллельно по слотам (решение владельца 2026-10-23): в слоте не
больше **3 активных рук** (`slot.max_active`, проверка в `activate_arm`), каталог
шире активного набора. Оценка числа наблюдений на руку: примерно 0,98 / d² при
разбросе награды 0,25 — около 25 при d = 0,2, около 44 при d = 0,15; поэтому
больше трёх рук в слоте не успевают набрать данные.

Награда — общая валюта «движение» (0,2 момент / 0,3 следующий день / 0,5 действие
за 72 ч, ADR-0001) для всех слотов; владелец подтвердил 2026-10-24, что для новых
практик она не меняется.

## Предлагаемое правило

1. **Когда оценивать.** Рука может быть заменена только после ≥ 25 наблюдений
   (завершённые пробы хотя бы с одной присутствующей компонентой награды).
2. **Критерий замены.** По нормальной апостериорной оценке (как в бандите):
   вероятность того, что среднее руки ниже лучшей руки слота не менее чем на 0,10,
   ≥ 0,90. Тогда рука снимается с активного набора (данные остаются).
3. **Кто входит.** Следующая из каталога слота по порядку: приор-среднее по
   убыванию, затем id; только допущенная по согласию класса (`consent`), без
   исключений (в том числе для разведки).
4. **Темп.** Не больше одной замены в слоте за 14 суток.
5. **Возврат.** Снятая рука может вернуться кандидатом не раньше чем через 90 суток.
6. **Разведка.** Принудительная разведка (инвариант 5, каждый 5-й выбор) идёт по
   активному и допущенному набору и не отключается.
7. **Ручной приоритет.** Владелец в любой момент включает/выключает руку; свободные
   сессии (`kind = 'free'`) в данные бандита и клапана не входят.

## Решения владельца 2026-10-24

- Пороги 25 / 0,10 / 0,90 / 14 / 90 — утверждены.
- Первые три руки слота `breath` выбирает владелец сам: нужна возможность выбора
  практики (наряд Н3-05), исполнитель не назначает их за него.
- Десять методик волны 1 образуют ОТДЕЛЬНЫЙ слот `methods` с теми же правилами
  (в слоте не больше 3 активных, ротация по тому же критерию). Сейчас все десять
  активны, поэтому введение потолка требует выбора владельца, какие три остаются
  активными, — делается в Н3-05 вместе с выбором, а не молча.

## Что уже в коде

`slot`, `consent`, `practice_protocol`; фильтр кандидатов бандита по согласию
(`eligible_arms`); `activate_arm` / `deactivate_arm`. Автоматическая замена —
следующий наряд после утверждения этого ADR.

## Дополнение Н4-07 (2026-11-03): допуск по уровням MIND-MASTERY

Статус: **правило утверждено владельцем 2026-11-02** (наряд #99, Шаг 0):
уровни MIND-MASTERY 1–5 становятся условием входа практики в активный набор
по числу завершённых сессий и минут системы, а не ручной разблокировкой.

1. **Данные правила.** Таблица `practice_admission` (UNIQUE system+level):
   минимум завершённых сессий И минут по системе для уровня 2–5. Источник —
   `progression.ts` шести систем MIND-MASTERY @ 2a26e75, доставлен конвертером
   Н4-01 (`scripts/mm-convert.py` → `seeds/mm/progression.json` → сид
   `seed_mm_catalog`); пороги совпадают с источником побайтно (тест пинит
   21 правило / 6 систем и эталонные строки: трансерфинг ур.5 = 40/600,
   дыхание ур.2 = 3/30). Уровень 1 всегда открыт; правил для него нет.
2. **Единица допуска.** Завершённая сессия системы = `trial` со статусом
   `completed` у руки этой системы (юнит системы — тот же фильтр семьи
   «наблюдение», что у апостериора и ротации). Минуты сессии — длительность
   практики (`arm.duration_min`, как в MIND-MASTERY). Свободные сессии и
   план дня в допуск НЕ входят (вне пути награды, Н4-03) — допуск
   консервативнее источника, размытие счётчика двойным учётом исключено.
3. **Семантика источника** (checkUnlock.ts @ 2a26e75): допуск =
   И сессии И минуты; нет правила для (system, level) — практика открыта
   («No rule for this level means it's unlocked»); руки без
   `practice_profile` (AERIS breath/methods волны 1) допуску не подчиняются.
4. **Где живёт гейт.** Вход в активный набор — только через `activate_arm`
   (ручной путь: запертая рука отказывает громко — `locked`, строка в
   `arm_journal`, состояние не меняется) и через кандидата ротации
   `rotation_candidate` (запертая рука пропускается — берётся следующая
   допущенная по порядку п.3 основного правила; слот пустеет только если
   допущенных кандидатов нет вовсе). Предикат — заявленный близнец:
   `mm_admission_locked` (arms) и SQL-литерал в `rotation_candidate`
   (bandit); третья копия — флаг `locked` в каталоге (информация
   владельцу). Обе стороны пинятся тестами.
5. **Дисклеймер.** Согласие с дисклеймером записывается данными:
   `consent` scope `disclaimer:v1` (экран при первом запуске Mini App —
   решение владельца A 2026-11-02: всё в Mini App; чат только указывает
   на него, пока записи нет). Запись идемпотентна (UNIQUE scope +
   INSERT OR IGNORE). Противопоказания практики (`practice_protocol.
   contraindications`) показываются ДО старта: в утреннем предложении
   чата, в строках плана и каталога Mini App; согласие по классу
   проверяется как раньше (инвариант 5 не тронут — разведка тоже).
6. **Экстренная остановка.** Кнопка доступна всегда (общая поверхность
   с Н4-04): чат «стоп»/«stop» и Mini App `/miniapp/stop`. Один эффект
   в данных: проба дня со статусом `proposed` уходит в `stopped` —
   новая строка статуса; все аналитические фильтры ключуются на
   `completed`/`missed`, поэтому остановка не фабрикует пропуск и не
   попадает в апостериор. Запись идемпотентна.
