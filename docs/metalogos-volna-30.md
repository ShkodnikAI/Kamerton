## Наряд №590 (P0, core/math): гауссово сэмплирование — `normal_sample` поверх общего PRNG, паритет TW↔VM

Labels: `naryad`, `P0`, `core`

**Мета:** Волна 30, P0, класс [core]. Внешний потребитель строит байесовский
бандит с сэмплированием Томпсона; без нормального распределения движок выбора
не реализуем ни в каком виде.

### Факт

- Общее состояние PRNG закрыто нарядом №372 (ADR-0141 Stage 1), паритет
  бэкендов проверяется `crosscheck_backends` (№373).
- В реестре 509 билтинов на 45 модулей; равномерный генератор есть,
  нормального сэмплера нет.
- Типизированные сигнатуры покрывают 165/509 (линия №467/№560) — новый билтин
  обязан прийти типизированным, а не пополнить хвост.

### Задача

1. `normal_sample(mean: Float, stddev: Float) -> Float` — преобразование
   Бокса–Мюллера поверх общего PRNG, без собственного состояния.
2. Детерминизм при фиксированном seed; второй вариант преобразования не
   вводится — одна реализация, одна точка отказа.
3. Типизированная сигнатура; классификация эффектов по №316 — чистая функция,
   ни одного эффекта.
4. `stddev <= 0` — громкий типизированный отказ, не NaN.

### Сделано, когда

- 10⁶ выборок: выборочные среднее и дисперсия в пределах 3σ от заданных.
- Фиксированный seed даёт побайтово идентичные последовательности на TW и VM.
- `crosscheck_backends` зелёный; мутационная проверка: подменённая константа
  `2π` ловится тестом.
- REFERENCE.md регенерирован, `scripts/gen_metrics.py --check` зелёный.
- Заглушек нет (§16.0-D).

### Границы

- Математический модуль билтинов + tests + REFERENCE.md. Ноль правок в audit,
  VM-инструкциях, serve.

### Зависимости и связи GitHub

- Блокирует Камертон Н1-05. Предшествует №594.

## Наряд №591 (P0, core/stats): спектральный контур — периодограмма Ломба–Скаргла для рядов с пропусками

Labels: `naryad`, `P0`, `core`

**Мета:** Волна 30, P0, класс [core]. Внешний потребитель меряет отклик
проекцией на доминантную частоту и проверяет периодичность ряда наблюдений с
пропусками. Текущая forecast-поверхность этого не умеет и не предназначена.

### Факт

- `series_make`/`forecast_next`/`forecast_state` (№440/№441): в дефолтной
  сборке считает только рунг `seasonal_naive`; `timesfm-2.5` за
  `--features timesfm` плюс SHA-проверенные веса (манифест №334 pending),
  `statsforecast` не вендорён.
- Спектральных билтинов в реестре нет. БПФ требует равномерной сетки, а ряд
  наблюдений заведомо с пропусками — отсюда Ломб–Скаргл, а не FFT.
- Поверхность forecast объявлена инструментальной, без интерпретаций
  (`docs/limitations.md`, строка `timeseries`). Новый контур наследует эту
  норму: числа и провенанс, без выводов.

### Задача

1. `lomb_scargle(times, values)` — нормированная периодограмма; частотная
   сетка выводится из длины и плотности ряда, не задаётся константами.
2. `spectral_peak(spectrum)` — доминантная частота, доля мощности в полосе
   вокруг пика, уровень значимости.
3. Degraded-loud: меньше порогового числа точек или вырожденный ряд — типизи‑
   рованный `Degraded(t)`, результат с `degraded=true`, никогда не тихо.
4. Границы метода документируются строкой в `docs/limitations.md` в том же PR
   (протокол №588): неравномерность, ложные пики на алиасах, отсутствие
   интерпретации.

### Сделано, когда

- Синтетика с известным периодом и 30% выбитых точек: пик в пределах 2% от
  истины на 10 независимых seed.
- Синтетика из белого шума: вердикт «периодичности нет» на заявленном уровне
  значимости, доля ложных срабатываний в пределах объявленного α.
- Второй независимый метод: сверка спектра с эталонными значениями на
  фиксированном наборе, посчитанными вне проекта.
- Паритет TW↔VM; REFERENCE.md регенерирован; строка в limitations.md в том же
  PR; заглушек нет (§16.0-D).

### Границы

- Новый модуль статистики + tests + REFERENCE.md + одна строка limitations.
- Forecast-лестница не трогается; никаких интерпретаций и советов.

### Зависимости и связи GitHub

- Камертон: инвариант 3, фазы M2 и M3.

## Наряд №592 (P1, core/http): пер-вызовный таймаут и устойчивый long polling

Labels: `naryad`, `P1`, `core`

**Мета:** Волна 30, P1, класс [core]. Внешний потребитель работает с Telegram
через long polling: запрос висит до 50 секунд и обязан различать таймаут,
обрыв и код ответа.

### Факт

- Отмена по дедлайну реализована на LLM-пути: SmartRouter через таймаут
  HTTP-клиента (№156), legacy через `call_with_deadline` (№248).
- Для обычных `http_get`/`http_post` пер-вызовный таймаут в документации не
  описан; Quality OS запрещает сетевые вызовы без таймаута и ретрая.
- Эффекты (№449/№316): сетевой билтин — ось network, аргумент под taint.

### Задача

1. Явный параметр таймаута у `http_get`/`http_post`, диапазон с верхней
   границей и громким отказом при выходе за неё.
2. Типизированные коды: таймаут, обрыв соединения, HTTP-статус — три разных
   исхода, не одна строка ошибки.
3. Ретрай оставлен вызывающему: язык не прячет повтор внутри.

### Сделано, когда

- Локальный медленный эндпоинт: таймаут срабатывает в заданный срок ±10%.
- Разрыв соединения на середине ответа даёт типизированную ошибку.
- Классификация эффектов не изменилась (ось network сохранена).
- Заглушек нет (§16.0-D).

### Границы

- HTTP-модуль билтинов + tests. Ноль правок в LLM-пути и SmartRouter.

### Зависимости и связи GitHub

- Блокирует Камертон Н1-06.

## Наряд №593 (P1, core/db, гейт владельца): откат миграции вне schema-as-code

Labels: `naryad`, `P1`, `core`, `process`

**Мета:** Волна 30, P1, класс [core]/[process]. Решение владельца, не
инженерный выбор: у внешнего потребителя критерий приёмки требует отката
миграции, а контур языка аддитивен по конструкции.

### Факт

- ADR-0060 и ADR-0175 §3.4: DDL-replay схемы ADDITIVE-ONLY
  (`CREATE TABLE IF NOT EXISTS`); drop и alter объявлены вне schema-as-code.
- ADR-0155, наряды №390/№412: необратимый SQL требует `Value::Grant`,
  покрытие scope — рантайм-свойство, статика держит Once-линейность.
- Камертон Н1-03 требует «применяется и откатывается» — сейчас невыполнимо.

### Задача

Выбрать один вариант и зафиксировать ADR:

- **A.** `migrate_down` под грантом: scope обязателен, `GRANT_SCOPE_MISMATCH`
  и TTL покрыты мутационной проверкой.
- **B.** Откат не поддерживается: строка в `docs/limitations.md` и правка
  критерия приёмки Камертона Н1-03 на «применяется идемпотентно, откат — через
  восстановление из бэкапа».

### Сделано, когда

- ADR принят и подписан владельцем; выбранный вариант реализован целиком.
- При A — грант обязателен, обе гейта (scope, TTL) пинятся красным→зелёным.
- При B — строка в limitations.md и обновлённый текст наряда Камертона.

### Границы

- При A — DB-модуль билтинов + tests + ADR. При B — только документы.

### Зависимости и связи GitHub

- Гейт для Камертона Н1-03. Решение до старта волны 1 Камертона.

## Наряд №594 (P1, testing/core): паритет чистой функции в cron-тике и в маршруте

Labels: `naryad`, `P1`, `core`, `testing`

**Мета:** Волна 30, P1, класс [testing]/[core]. Самый опасный класс для
внешнего потребителя: движок выбора считается в тике, отчёт отдаётся
маршрутом, и расхождение бэкендов означает, что система принимает одно
решение, а показывает другое.

### Факт

- ADR-0175 §4: контекст cron-тика — конструкция TW-интерпретатора;
  VM-маршруты — отдельный путь, не унифицированный.
- `mlog serve` с 2026-09-21 держит VM по умолчанию (ADR-0171).
- `docs/limitations.md`, раздел TW/VM: serve и run МОГУТ давать разные
  результаты для одной программы; корпус классов живёт в №465.
- Следствие для Камертона: `normal_sample` и арифметика распада исполняются
  на двух разных бэкендах в одной программе.

### Задача

1. Контракт: чистая функция без эффектов даёт идентичный результат в теле
   cron-тика и в теле маршрута при одном seed.
2. Тест паритета на программе-образце: тик считает, маршрут пересчитывает,
   результаты сверяются побайтово.
3. Класс добавлен в дифд-фаззер №465; расхождение — громкий фейл с
   воспроизводящим входом.
4. Production-правки в этом наряде запрещены: найденное расхождение
   оформляется отдельным ремонтным нарядом.

### Сделано, когда

- Программа-образец с `normal_sample`, экспонентой и сравнением даёт
  идентичный результат в тике и в маршруте на 100 прогонах, оба бэкенда.
- Класс в корпусе фаззера; прогон зелёный на main; стоп-лист №465 не растёт.
- Заглушек нет (§16.0-D).

### Границы

- Только тесты и корпус фаззера. Ноль production-правок.

### Зависимости и связи GitHub

- Строго после №590. Блокирует Камертон Н1-05.

## Наряд №595 (P2, core/time): календарная арифметика в UTC

Labels: `naryad`, `P2`, `core`

**Мета:** Волна 30, P2, класс [core]. Внешнему потребителю нужна разница дат в
сутках для экспоненциального распада и арифметика синодического месяца для
фазы Луны.

### Факт

- Forecast работает с рядами, но публичной поверхности разбора и формата
  ISO-дат в реестре не описано.
- Камертон Н1-05 считает возраст отклика в сутках, Н1-07 — лунный день без
  внешних библиотек.
- Локальные геттеры времени дают сдвиг на сутки западнее Гринвича —
  вычисления обязаны идти в UTC.

### Задача

1. `now_unix()`, `date_parse_iso(s)`, `date_diff_days(a, b)`,
   `date_format_iso(t)`.
2. Все вычисления в UTC; таймзона применяется только при отображении и
   параметром, не глобально.
3. Невалидная строка — громкий типизированный отказ, не нулевая дата.

### Сделано, когда

- 12 контрольных дат сверены со вторым независимым источником.
- Переход через полночь, високосный год и конец года покрыты тестами.
- Паритет TW↔VM; REFERENCE.md регенерирован; заглушек нет (§16.0-D).

### Границы

- Модуль времени + tests + REFERENCE.md.

### Зависимости и связи GitHub

- Камертон Н1-05, Н1-07.

## Отдельно: голосовой контур — закрыт без нарядов в язык

Проверено по `docs/limitations.md` и решено владельцем. Нарядов в эту волну
не добавляет.

`stt_transcribe` — mock-first поверхность; реальный инференс PARKED нарядом
№334 за аппаратным гейтом №294 (≥64 ГБ RAM, ≥40 ГБ диска, GPU). Хранение
голосового отпечатка с наряда №512 запрещено на уровне рантайма
(`[VOICE_INSECURE_STORE]`).

Решение владельца: **клонирование голоса снято с дорожной карты насовсем** —
озвучка идёт готовым женским голосом, отпечаток не возникает, запрет №512
к проекту не относится и ждать №517 не нужно.

Следствие: и TTS, и распознавание отклика работают внешними процессами на
домашнем сервере через существующий exec-гейт. Голосовых билтинов проект не
заказывает ни в этой волне, ни в последующих.
